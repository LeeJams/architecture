# React 전환

기존의 카드 목록 → 넷플릭스 상세 화면과 3열 구성도, 기술별 글, 명시적인 현재 → 대체 관계를 React 컴포넌트로 옮겼습니다. 원고·출처·학습용 설정·기술 로고를 유지하면서 화면 상태와 렌더링을 분리했습니다.

## 선택한 도구

| 도구 | 쓰는 곳 | 범위 |
| --- | --- | --- |
| React·React DOM | 컴포넌트·상태·이벤트·용어 도움말 portal | 화면 전체 |
| Vite | JSX 개발 서버·프로덕션 번들·로컬 에셋 처리 | 개발·빌드 |
| [Motion](https://motion.dev/docs/react) | 짧은 등장·내용 변경·버튼 눌림·계산 막대 | `LazyMotion`과 `m`, `MotionConfig reducedMotion="user"` |
| [Ladle](https://ladle.dev/) | 실제 React 컴포넌트를 단독으로 조작하는 디자인 작업대 | 개발 전용, 서비스 번들 제외 |
| Playwright·Chromium | 키보드·반응형·오프라인·기본 브라우저 UI 검증 | 개발 전용 |

외부 Figma 연결은 제공되지 않아 Ladle에서 기존 색상·서체·여백을 사용한 컴포넌트 상태를 직접 확인했습니다. Ladle의 Controls에서 오른쪽 패널의 기술과 탭, 대체 제품을 바꿀 수 있습니다. HTTP 조건별 응답과 다운로드/재생 시간 비교도 직접 조작합니다. 화면은 `docs/images/react-design-workbench.png`에 기록했습니다.

기존 CSS와 기본 버튼·탭·dialog·Popover·View Transition을 사용합니다. 두 개의 화면과 주제 해시는 History API로 처리하고, 선택 상태는 Context와 reducer가 관리합니다. 별도 라우터·전역 상태 패키지·그래프 렌더러·아이콘 패키지는 추가하지 않았습니다. Ladle과 호환되는 Vite 6·React 플러그인 4 조합은 잠금 파일로 고정합니다.

## 컴포넌트와 데이터

- `Library`·`DesignPage`: 한국어 소개·서비스 카드·본문 구성.
- `Explorer`·`Diagram`·`Inspector`: 선택 단계·노드·기술로 강조 경로와 오른쪽 설명을 결정합니다. SVG의 위치·라벨·브랜드 이미지를 유지합니다.
- `TechnicalDepth`: 핵심 원리·조건별 요청/응답·관측/진단. 본문과 상세 창이 같은 컴포넌트·원고를 사용합니다. 각 인스턴스의 조건 선택은 서로 독립적입니다.
- `TechnologyReader`: 8개 주제와 계산기. 입력 값·유효성·계산 결과가 React 상태로 연결됩니다.
- `TechnologyDialog`: 기본 dialog가 모달·Escape·포커스 복원을 맡고 React가 선택된 원고를 렌더링합니다. 취소·닫기를 상태와 동기화해 즉시 다시 열어도 동작합니다.
- `Alternatives`: 9개 대체 관계와 2개 저장소 구현 예시를 구분하고 교체 위치·연결할 기존 역할을 보여줍니다.
- `Glossary`: 텍스트를 React 요소로 분해해 용어 버튼을 렌더링합니다. MutationObserver·innerHTML·전역 DOM 교체를 사용하지 않습니다. 버튼·링크·코드·SVG 내부에는 설명 버튼을 넣지 않습니다. 모달 안에서 연 용어 도움말은 해당 모달 안으로 portal합니다.
- `src/data`: 기술 설명·계층·9단계 흐름·제품·출처·용어. 설정 코드와 학습용 수치, 검증된 설명의 범위를 그대로 보관합니다.

React ref를 통한 DOM 접근은 브라우저 API와 측정·스크롤·포커스에 한정합니다. 앱 상태를 바꿔 화면을 그리는 동작은 JSX와 React 이벤트가 맡습니다. 기존 전역 스크립트와 문자열 HTML 렌더러는 제거했습니다.

## 움직임과 접근성

| 변화 | 표현 |
| --- | --- |
| 서비스 카드 ↔ 상세 | Chrome 기본 View Transition, 표지·제목·배경 연결 |
| 단계 선택 | 선택 배경·관련 노드·경로 강조·진행 막대 |
| 설명/서버 계층/조건 변경 | 160ms 내용 등장, 선택 상태는 즉시 표시 |
| 대체 카드·기술 창 | 160~180ms 짧은 등장 |
| ABR 처리량 변경 | 재생 4초와 다운로드 시간을 같은 비율의 막대로 비교 |

모션 감소 설정에서는 이동 효과와 경로 애니메이션을 끕니다. 키보드 탭 이동·Home/End·Space·Enter, 모달 포커스 복원, 도움말을 먼저 닫는 Escape 동작을 유지합니다. 움직임을 기다려야 읽거나 조작할 수 있는 단계는 두지 않습니다.

## 빌드와 검증

웹 빌드는 React·Motion·서비스 번들을 분리하고 로컬 이미지·서체를 해시 파일로 내보냅니다. 참고 이미지는 lazy loading으로 읽습니다. `build-standalone.mjs`는 같은 소스를 에셋 포함 모드로 빌드하고 JS·CSS·아이콘·라이선스를 안전하게 HTML에 포함합니다. 코드에 들어 있는 `$&` 같은 문자열이 치환 연산으로 해석되지 않도록 콜백 치환을 사용합니다. 남은 외부 런타임 경로가 있으면 빌드를 실패시킵니다.

`npm test`는 빌드된 `dist/`를 임시 서버에서 검사합니다. 단일 HTML은 첫 문서만 제공한 뒤 브라우저를 오프라인으로 전환해 추가 요청이 없는지 검사합니다. UI 검사는 전체 이미지의 유효성을 확인하려고 테스트에서만 지연 이미지의 로딩을 강제합니다.

기존 19개 폭·1,026개 배치 상태, 기본 화면 전환, 기술 글·계산기, 조건별 54개 상세 상태, 대체 관계, 용어 설명 검사에 React 상태·기본 브라우저 UI 동기화를 포함했습니다. `npm run design:build`로 작업대도 별도로 빌드합니다.

## 공용 기술 컴포넌트

`TechnologyCatalogue`는 `?view=technologies` 경로의 분류·검색 화면입니다. 제품의 ID·제공사·심벌·정의·예제는 `technology-catalogue.js`에 모았습니다. `TechnologyCard`는 목록과 사례에서 함께 사용하고 `TechnologyInfo`는 같은 원고로 제품 자체의 상세를 표시합니다. `usage`는 사례에서의 역할만, 공용 원고는 일반적인 제품 기능만 담습니다.

기존 기본 dialog에 `catalogue` 관점을 추가했습니다. 사례에서 연 상세는 “이 사례에서의 사용 / 기술 자체 정보”를 전환할 수 있고, 제품 목록에서 연 상세는 일반 정보로 시작합니다. 같은 모달에서 관점·관련 기술을 바꾸므로 모달을 겹쳐 열지 않습니다. 기술 목록과 카드·상세는 Ladle에서도 검토합니다.
